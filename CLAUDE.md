# CLAUDE.md — gastosai-backend

Spring Boot 4 (Java 25) REST API for gastosai, an AI-assisted expense tracker for a
Philippine audience. **This repo owns and publishes the API contract.** Read
`CONTRACT.md` first, then `KNOWN-GAPS.md` for the places today's code does not yet meet
the invariants below.

---

## 1. Invariants

1. **Source of API truth.** springdoc generates `openapi.json`; it's published as
   `@tetengdev/gastosai-api-contract` for clients to pin. A controller/DTO change is
   a public contract change — version it per `CONTRACT.md`.
2. **Business logic in the domain/service layer, never in a controller.**
3. **Money is never floating point.** Currency explicit, default `PHP`. Served today as
   `BigDecimal(19,4)`; the contract's integer-centavos target is tracked in `KNOWN-GAPS.md`.
4. **Timestamps stored UTC, served ISO 8601 `+08:00`.** Day/month logic in
   `Asia/Manila`. Naive timestamps are bugs.
5. **Schema owned by Flyway migrations, `ddl-auto=validate`.** No Supabase dashboard
   schema edits. Migrations are append-only and expand-contract (§5).
6. **AI is backend-only and behind a port.** OpenAI/Claude are adapters selected by
   `GASTOS_AI_PROVIDER`; no provider SDK type in the domain; no key ever leaves to a
   client. Redact card/email/phone before any prompt; meter into `ai_usage`; 429 on
   cap; ADMIN bypass; cached insights don't count.
7. **No secrets in the repo.** Env vars only.

---

## 2. Stack & versions

- Java 25, Spring Boot 4.1.0.
- **Maven** — `mvnw.cmd` / `mvnw`. Not Gradle.
- Spring Data JPA over PostgreSQL 17 (Docker `:5433` local, Supabase prod), Flyway.
- `springdoc-openapi-starter-webmvc-ui:3.0.3` → spec + Swagger UI. Confirmed working on
  Spring Boot 4.1 / Framework 7.
- Before adding/upgrading any dependency, confirm Framework-7 compatibility.

## 4. Contract publishing

- `OpenApiContractTest` (in the normal test run) reads `/v3/api-docs` via MockMvc and writes
  `contract/openapi.json`. No database, no separate process, no extra Maven profile —
  `./mvnw test` regenerates it. The same test asserts every `@RestController` endpoint appears
  in the spec, and that no money-bearing field is float/double.
- Output is key-sorted and indented, so regeneration is byte-identical unless the API really
  changed. **CI fails if the committed spec is stale** — regenerate and commit with the change.
- `.github/workflows/publish-contract.yml`: on a **`contract-v*`** tag, runs the suite, verifies
  the spec is current, and `npm publish`es `contract/` to GitHub Packages.
- The contract version is deliberately **not** the application version. The app is on `0.x`
  and tags `v*`; the contract starts at `1.0.0` and tags `contract-v*`. Most app releases do
  not change the API surface, and republishing an unchanged spec under a new number would make
  the client's pin meaningless.
- Version bump = compatibility (`CONTRACT.md`): non-breaking → minor; breaking →
  major + new `/api/v2` path with the old path kept live.

---

## 5. Migrations (expand-contract — mandatory)

- New migration = expand only, unless it's the later contract step of a shape already
  expanded and backfilled. Never rename/drop/retype a column deployed code reads in a
  single step.
- Every migration PR states its step (expand | backfill | contract) and confirms the
  pre-migration backup path runs (`scripts/backup-before-migrate.sh` / `.ps1`). Those
  scripts fail closed: no restorable dump, no migration.
- Append-only; never edit an applied migration.

---

## 6. Testing

- Domain/service unit tests, no Spring context.
- `OpenApiContractTest` asserts the spec generates and covers every controller.
- AI and outbound HTTP mocked. **Never call live OpenAI/Claude.**
- Golden-file parser tests over Filipino/Taglish inputs.
- Repository/migration tests run on H2 today; the Testcontainers target is in `KNOWN-GAPS.md`.

---

## 7. Definition of done

1. `mvnw test` passes; migrations apply clean on empty Postgres.
2. Spec regenerates and `contract/openapi.json` is committed; if the surface changed, publish a
   new contract version and note whether it's minor or major.
3. Any schema change is expand-contract with a backup path.
4. Prod image built with a pinned tag, never `:latest`.
5. No float money, no naive timestamps, no provider SDK in domain, no leaked key,
   no secret.

---

## 8. Working agreement

**Do without asking:** add non-breaking endpoints, tests, expand migrations, refactor
within a layer, improve logging.

**Ask first:** any breaking API change (needs major + `/api/v2` + client migration), a
non-expand-contract schema change, a dependency (check Framework 7), changing the AI
provider/quota model or auth, anything touching deploy/rollback.

**Never do:** business logic in a controller, float money, naive timestamps, schema
change outside a migration, provider SDK type in domain, key reachable by a client,
`:latest` in prod compose, publish a breaking contract before clients can migrate.

## 9. Commands

```bash
docker compose up -d                # local Postgres :5433
./mvnw spring-boot:run              # Flyway then :8080, Swagger at /swagger-ui.html
./mvnw test                         # full suite; regenerates contract/openapi.json
./mvnw verify                       # tests + JaCoCo report

scripts/project-version.sh          # the version the release/image workflows use
DB_URL=... DB_USERNAME=... DB_PASSWORD=... scripts/backup-before-migrate.sh
```

PowerShell equivalents (`.\mvnw.cmd`, `.\scripts\backup-before-migrate.ps1`) work the same.
